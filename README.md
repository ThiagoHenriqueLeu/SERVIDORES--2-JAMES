# SERVIDORES--2-JAMES

## CatalogoApp

Aplicacao web em Spring Boot para gerenciamento de produtos, categorias, usuarios e auditoria de alteracoes.

O sistema permite cadastrar produtos, controlar estoque, filtrar por categoria, autenticar usuarios e registrar historico detalhado de edicoes feitas nos produtos.

## Tecnologias utilizadas

- Java 17
- Spring Boot 3.4.2
- Spring MVC
- Spring Data JPA
- Spring Security
- Thymeleaf
- PostgreSQL
- Bootstrap 5
- Maven Wrapper
- Docker, opcional para rodar o PostgreSQL

## Funcionalidades

- Login com Spring Security.
- Usuario administrador inicial criado automaticamente.
- Cadastro de usuarios.
- Cadastro de categorias.
- Cadastro, listagem, edicao e exclusao de produtos.
- Busca de produtos por nome.
- Filtro de produtos por categoria.
- Controle de quantidade em estoque.
- Validacao para impedir estoque negativo.
- Mensagem de sucesso ao cadastrar ou editar produto.
- Tela de auditoria exclusiva para administrador.
- Registro de todos os campos alterados no produto.
- Auditoria mostra valor anterior, valor novo, usuario, data e motivo.
- Popup opcional para informar motivo ao alterar preco ou estoque.
- Permite salvar alteracoes mesmo com motivo vazio.
- Bloqueio de rotas administrativas para usuarios comuns.

## Configuracao do Banco de Dados PostgreSQL

Este projeto utiliza PostgreSQL como banco de dados principal.

### Pre-requisitos

- PostgreSQL instalado, ou Docker instalado.
- Java 17 instalado.
- Opcional: pgAdmin para visualizar o banco.

## 1. Criar banco e usuario

No projeto atual, o `application.properties` esta configurado assim:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/catalogo_db
spring.datasource.username=postgres
spring.datasource.password=123456
```

Se for criar manualmente no PostgreSQL, execute:

```sql
CREATE DATABASE catalogo_db;

ALTER USER postgres WITH PASSWORD '123456';
```

Se preferir usar um usuario separado:

```sql
CREATE DATABASE catalogo_db;

CREATE USER catalogo_user WITH PASSWORD '123456';

ALTER ROLE catalogo_user SUPERUSER;
```

Nesse caso, altere o `application.properties` para:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/catalogo_db
spring.datasource.username=catalogo_user
spring.datasource.password=123456
```

## 2. Criar tabelas

O projeto usa:

```properties
spring.jpa.hibernate.ddl-auto=update
```

Por isso, o Hibernate cria e atualiza as tabelas automaticamente ao iniciar a aplicacao.

Mesmo assim, a estrutura atual do banco e esta:

```sql
CREATE TABLE tb_categoria (
    id_categoria BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(255) NOT NULL
);

CREATE TABLE tb_produto (
    id_produto BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    data_atualizacao TIMESTAMP,
    nome VARCHAR(100) NOT NULL,
    quantidade INTEGER NOT NULL,
    valor NUMERIC(38,2) NOT NULL,
    id_categoria_fk BIGINT NOT NULL,
    motivo_alteracao VARCHAR(500),

    CONSTRAINT fk_categoria
        FOREIGN KEY (id_categoria_fk)
        REFERENCES tb_categoria(id_categoria)
);

CREATE TABLE tb_auditoria_produto (
    id_auditoria BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    campo_alterado VARCHAR(255) NOT NULL,
    data_alteracao TIMESTAMP NOT NULL,
    id_produto BIGINT,
    motivo VARCHAR(500),
    nome_produto VARCHAR(255) NOT NULL,
    usuario VARCHAR(255) NOT NULL,
    valor_anterior VARCHAR(500),
    valor_novo VARCHAR(500)
);

CREATE TABLE tb_usuario (
    id_usuario BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username VARCHAR(255) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(255)
);
```

## Auditoria de produtos

A auditoria registra cada campo alterado em uma edicao de produto.

Campos registrados:

- Produto.
- Campo alterado.
- Valor anterior.
- Valor novo.
- Motivo.
- Usuario que alterou.
- Data e hora da alteracao.

Exemplo:

```text
Produto: Notebook
Campo alterado: Preco
Valor anterior: 3500.00
Valor novo: 3650.00
Motivo: Reajuste de fornecedor
Usuario: admin
```

Quando o preco ou o estoque sao alterados, o sistema exibe um popup para informar o motivo. O motivo e opcional, entao o usuario pode salvar com o motivo vazio.

Quando o motivo fica vazio, a auditoria registra:

```text
-
```

## Consultas uteis no banco

Consultar categorias:

```sql
SELECT * FROM tb_categoria;
```

Consultar produtos:

```sql
SELECT
    p.id_produto,
    p.nome,
    p.quantidade,
    p.valor,
    c.nome AS categoria,
    p.motivo_alteracao,
    p.data_atualizacao
FROM tb_produto p
JOIN tb_categoria c
    ON c.id_categoria = p.id_categoria_fk
ORDER BY p.id_produto;
```

Consultar auditoria:

```sql
SELECT
    id_auditoria,
    id_produto,
    nome_produto,
    campo_alterado,
    valor_anterior,
    valor_novo,
    motivo,
    usuario,
    data_alteracao
FROM tb_auditoria_produto
ORDER BY data_alteracao DESC;
```

Consultar usuarios:

```sql
SELECT id_usuario, username, role FROM tb_usuario;
```

## Fluxo da aplicacao

1. O usuario acessa `/produtos`.
2. A listagem de produtos e exibida.
3. Para acoes administrativas, o usuario faz login em `/login`.
4. O administrador pode cadastrar, editar e excluir produtos.
5. Ao salvar produto, o `ProdutoController` recebe os dados do formulario.
6. O `ProdutoService` valida as regras de negocio.
7. Se a quantidade for negativa, o produto nao e salvo.
8. Se o produto for novo, ele e cadastrado.
9. Se o produto for editado, o sistema compara o estado antigo com o novo.
10. Para cada campo alterado, uma linha e salva em `tb_auditoria_produto`.
11. O usuario volta para `/produtos` com mensagem de sucesso.
12. A tela `/produtos/auditoria` mostra o historico das alteracoes.

## Regras de negocio

- Produto precisa ter nome.
- Produto precisa ter valor positivo.
- Produto precisa ter quantidade.
- Quantidade nao pode ser negativa.
- Produto precisa ter categoria.
- Ao editar produto, todas as alteracoes sao registradas na auditoria.
- Motivo da alteracao e opcional.
- Apenas administradores podem alterar dados.

## Problemas comuns

### Erro: Connection to localhost:5432 refused

Significa que o PostgreSQL nao esta rodando.

Se estiver usando Docker:

```powershell
docker start catalogo-postgres
```

Depois rode o projeto novamente:

```powershell
.\mvnw.cmd spring-boot:run
```

### Porta 8080 ja esta em uso

Algum processo ja esta usando a porta 8080.

No Windows:

```powershell
netstat -ano | findstr :8080
```

Depois encerre o processo pelo PID:

```powershell
Stop-Process -Id NUMERO_DO_PID -Force
```
